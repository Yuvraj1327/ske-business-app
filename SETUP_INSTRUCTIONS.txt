BRANDING SETUP — ONE-TIME STEPS AFTER APPLYING THIS DELTA
============================================================

1. Confirm assets/logo.png is in place
   ------------------------------------
   You said it's already at flutter_app/assets/logo.png — pubspec.yaml now
   declares it under `flutter: assets:`, and the app's CompanyLogoMark
   widget (used on Login, Sidebar/Drawer, AppBar area, and Settings) now
   loads it via Image.asset('assets/logo.png'). If the file isn't at that
   exact path, the widget falls back to a plain "SK" monogram instead of
   crashing — so double check the path if you don't see the real logo.

2. Generate the Android launcher icon, Web favicon/app icons, and splash
   screen from the same logo (this is what makes it "appear in release
   builds", since these are real per-density files written into android/
   and web/, not just an in-app widget):

       cd flutter_app
       flutter pub get
       flutter pub run flutter_launcher_icons
       flutter pub run flutter_native_splash:create

   Both tools are already configured in pubspec.yaml to read
   assets/logo.png and use your brand navy (#173B63) as the theme/splash
   background accent. Re-run these two commands any time you replace the
   logo file.

3. Rebuild
   -------
       flutter run            # or flutter build apk / flutter build web

WHY I DIDN'T GENERATE THE ICON FILES MYSELF
============================================================
I don't have your project's android/ or web/ platform folders in my build
environment (only the lib/ Dart source is tracked here) — I can't write
per-density PNGs into folders I don't have. Configuring
flutter_launcher_icons/flutter_native_splash in pubspec.yaml is also the
correct, standard way to do this in Flutter (rather than hand-copying
resized PNGs into mipmap folders), and it's a one-time, two-command step
on your end.
